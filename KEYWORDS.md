## How to use this list

searching for — names, aliases, acronyms, spellings, and the vocabulary of
sources across the spectrum, hostile ones included. Listing a term asserts

its pages can be *found*, not endorsed. Every claim about the subject lives in

## Search traps

Hand-written; **outside the generated block on purpose** — regeneration leaves
this section alone. Every entry below was observed in this repo's data, in a
sibling repo's `data/`, or in the shared `cronologia/archive` vault during the
session that wrote it. Nothing is inferred. Each entry gives the trap and the
term that actually works.

### 1. Search the term **id**, not the display name

This repo's search key is the `id` — it is a permanent public URL
(`https://cronologia.github.io/glossary/<id>/`), it is **identical in every
locale**, and the project builds treat it as an API symbol (`adr/0001`;
AGENTS.md "Ids are forever"). It is the most reliable search handle in the
whole family. Display names are translated; ids never are.

Verified counts, run over the sibling `data/` directories:

| search string | `fsspx` | `tariqa` | `perennialism` |
|---|---|---|---|
| `Philosophia perennis` (the display name) | **0** | **0** | 3 |
| `philosophia-perennis` (the id) | 1 | 1 | 2 |
| `Traditionalist School` (display name) | 3 | 7 | 4 |
| `traditionalist-school` (the id) | 3 | **10** | 2 |

The display name of `philosophia-perennis` returns **zero** hits in two of the
three repos that carry the term. The id finds it in both. Where both work, the
id still ranks the densest file correctly (`tariqa`: 10 vs 7).

### 2. `[[term-id]]` markers — the display text is localized, the id is not

Project sites cite terms with a marker, in two forms, both observed in
`fsspx/data/chronology.json` and `tariqa/data/chronology.json`:

- bare — `[[tariqa]]`, `[[dhikr]]`, `[[silsila]]`, `[[sedevacantism]]`
- piped alias — `[[term-id|whatever the sentence needed]]`

**The piped form is where naive searches die**, because the alias is inflected
and translated while the id stays fixed. Real marker strings from the sibling
datasets, one id each:

- `[[philosophia-perennis|Perennial philosophy]]` · `[[philosophia-perennis|Filosofia perene]]` (pt) · `[[philosophia-perennis|Filosofía perenne]]` (es)
- `[[canonical-irregularity|canonically irregular]]` · `[[canonical-irregularity|canonicamente irregular]]` (pt) · `[[canonical-irregularity|canónicamente irregular]]` (es — note the accent moves)
- `[[suspension-a-divinis|suspended a divinis]]` · `…|suspenso a divinis]]` · `…|suspendido a divinis]]`
- `[[excommunication|excommunication]]` · `…|excomunhão]]` · `…|excomunión]]`
- `[[schism|schismatic]]` · `[[schism|cismática]]`
- `[[sedeprivationism|sedeprivationist]]` · `[[sedeprivationism|sedeprivacionistas]]`
- `[[sedevacantism|Sedevacantists]]` · `[[sedevacantism|sedevacantistas]]`
- `[[traditionalist-school|Escola Tradicionalista]]` (pt) · `[[traditionalist-school|Escuela Tradicionalista]]` (es)
- `[[khalifa|khalifas]]` · `[[cdf-ddf|DDF]]` · `[[latae-sententiae|latae sententiae]]` · `[[motu-proprio|motu proprio]]` · `[[pia-unio|pia unio]]`

**What works:** grep `[[<id>` (open brackets plus id, no closing bracket) to
catch bare and piped forms at once. Searching the glossary's own display name —
`Canonical irregularity ('no canonical status')`, `CDF / DDF`, `Bay'ah` — will
not match any marker, because no marker ever contains it.

`[[term-id]]` **literally** appears in `fsspx`, `tariqa`, `perennialism` and
`rcc` — it is the placeholder in their prose docs, not a real link. Exclude it.

### 3. The id grammar (derived from all 34 ids in this dataset)

Every id matches `^[a-z0-9-]+$` — lowercase ASCII, hyphen-separated, 4 to 22
characters, **no diacritics, no apostrophes, no spaces, no slashes,
no parentheses**. The display name is mangled into it by these observed
transformations, each of which breaks a literal search:

| display name | id | what was dropped |
|---|---|---|
| `Contra-Revolução (Counter-Revolution)` | `contra-revolucao` | diacritic + parenthetical |
| `Teología del pueblo` | `teologia-del-pueblo` | diacritic |
| `Batismo no Espírito Santo (baptism in the Spirit)` | `batismo-no-espirito` | diacritic + **truncated** |
| `Bay'ah` | `bayah` | apostrophe |
| `CDF / DDF` | `cdf-ddf` | slash → hyphen |
| `Encontro / Encuentro` | `encontro-encuentro` | slash → hyphen |
| `Foro vs Grupo (São Paulo / Puebla)` | `foro-vs-grupo` | diacritic + parenthetical |
| `Canonical irregularity ('no canonical status')` | `canonical-irregularity` | quoted parenthetical |
| `Pia unio (pious union)` | `pia-unio` | parenthetical |
| `CEBs (comunidades eclesiais de base)` | `cebs` | the entire expansion |
| `Tariqa (and the Maryamiyya)` | `tariqa` | parenthetical |
| `Preferential option for the poor` | `preferential-option` | **truncated** |

So `cebs` will not find "comunidades eclesiais de base" and vice versa; search
both. Same for `batismo-no-espirito` / "Espírito Santo" and
`preferential-option` / "for the poor".

### 4. The i18n caches are keyed by English string, not by id

`data/i18n/pt.json` and `es.json` are machine-translation caches keyed by the
**English source string**. Verified: `latae-sententiae` and
`philosophia-perennis` return **0** hits in `data/i18n/pt.json`, while both
appear in `data/glossary.json`. Do not conclude a term is untranslated because
its id is absent from a locale cache — look up the English `term`/`definition`
string instead (`Latae sententiae` → 4 hits in `pt.json`). These files are
generated; never hand-edit them.

### 5. ASR manglings in the vaulted transcripts

Observed by counting `cronologia/archive/transcripts/` this session. The
auto-caption corpora mangle proper names systematically, and the **correct**
spelling is the one that fails:

- **`Lefebvre`** — the correct spelling returns **3** hits across the whole
  transcript corpus. `Lefebre` returns **74** and `LeFevre` returns **66**.
  A search on the correct spelling misses ~98% of the material. Also present:
  `lefevrista`, `lefebrismo`, `lefebrista`, `lefebriano`, `lefevrismo`.
- **`Schuon`** — `Shuan` (42 across cases) and `Chuan` (6) alongside the
  correct form. `Shuan` is not a typo to fix, it is a search term.
- **`tariqa`** — observed as `Tarik`, `Tariká`, `Tarica`, `Tarique`, `tarika`,
  `itarika`, `tariqah`, `tariqas`, and the coinage `tariqueira`. Search
  `tari` as a stem and read context.
- **`shaykh`** — the transcripts overwhelmingly write `Sheik`/`Sheikh`/`sheik`,
  not the glossary's `shaykh`.
- **Zero-hit warning:** `dhikr`, `zikr` and `silsila` return **0** across the
  entire transcript corpus, though `tariqa`-family forms return 65+. The
  concepts may well be discussed; the words as spelled are not there. Do not
  read the zero as absence of subject matter.

### 6. Ambiguous referents and false friends

Concrete, from this dataset's own disambiguation work and from the vault:

- **`integrismo` ≠ `integralismo`.** The glossary defines *integrismo*
  (French *intégrisme*) and states explicitly that it is **distinct from the
  Brazilian integralismo of the 1930s**. Searching "integralismo" retrieves a
  different movement.
- **Catholic traditionalism ≠ the `traditionalist-school`.** Same English word,
  two unrelated subjects: the Guénon–Schuon school of comparative metaphysics
  vs the SSPX's movement about liturgy and Vatican II. The `variants` field
  also flags **Evolian 'Traditionalism'** as a third referent. Always qualify.
- **`philosophia-perennis` has four distinct lineages** per its own definition
  (Steuco, Leibniz, Huxley, Guénon/Schuon). A hit tells you nothing until you
  know which one.
- **`encontro`/`encuentro`** is the ordinary Portuguese/Spanish noun for
  "meeting" — capitalized it is the numbered meeting series. Expect a very low
  signal-to-noise ratio on the lowercase form.
- **Foro de São Paulo (1990) ≠ Grupo de Puebla (2019)** — `foro-vs-grupo`
  exists purely to stop this conflation.
- **`khalifa`** in Sufi usage (a shaykh's designated deputy) is not the
  political *caliph*, though it is the same word. **`muqaddam`** likewise names
  civil and military officials outside Sufism.
- **`Tarik`/`Tariká`** in the Portuguese transcripts is not always the Sufi
  order — in `transcript-121-…` it also appears in channel-address patter
  ("Fala galerinha da Tariká"). Check context before counting a hit.

### 7. Terms of art: do not translate when searching

Search these in the source language. The glossary id is the stable handle for
each:

- **Latin, canon law** — *latae sententiae* (`latae-sententiae`; contrast
  *ferendae sententiae*), *suspension a divinis* (`suspension-a-divinis`),
  *motu proprio* (`motu-proprio`), *pia unio* (`pia-unio`),
  *philosophia perennis* (`philosophia-perennis`). Sources cite canons as
  `can. 751`, `can. 1314`, `cann. 294–297` — search the canon number, which is
  language-independent, rather than the doctrine's name.
- **Arabic, Sufism** — *tariqa* (`tariqa`), *silsila* (`silsila`), *muqaddam*
  (`muqaddam`), *khalifa* (`khalifa`; the office is *khilafat*), *zawiya*
  (`zawiya`; the Persianate equivalent is *khanqah*, the Ottoman-Turkish
  *tekke* — different words, same institution), *dhikr* (`dhikr`; also *zikr*),
  *bay'ah* (`bayah`; also *baya*, *bay'at*).
- **Portuguese/Spanish, not to be Englished** — *comunidades eclesiais de base*
  (`cebs`), *teología del pueblo* (`teologia-del-pueblo`), *Contra-Revolução*
  (`contra-revolucao`), *carisma* (`carisma`), *prelazia* (`prelature`).

each term's `projects[]`:

**Trap:** the values in `projects[]` are **project codes, not repo names**, and
three of the eight have no repo in the family yet. `tl` (liberation theology,
9 terms), `fsp` (Foro de São Paulo, 4), `tfp` (2) and `grupopuebla` (2) are
listed as out of scope in AGENTS.md. Filtering terms by `projects: "fsspx"`
works; searching for a repo called `tl` does not.

**Trap:** the project repos do **not** read this dataset at build time. They
validate markers against a **pinned vendored copy** of the ids at
`<project>/data/glossary-terms.json` (present in `fsspx`, `tariqa` and
`perennialism`). If an id you see here is missing there, that project has not
re-synced — that is the file to grep to learn which ids a given project build
will accept.
